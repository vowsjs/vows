# Vows V2 Modernization Logic

This document captures the reasoning, trade-offs, and decisions made during the modernization of vows from a 2016-era CommonJS library to a 2026-era ES modules library.

## Reference Implementation

The modernization follows conventions from `~/Git/indexzero/flatlock`, which represents the target modern Node.js project structure.

## High-Level Decisions

### 1. ES Modules Over CommonJS

**Decision**: Full ES modules (`"type": "module"`)

**Rationale**:
- Node.js has stabilized ESM support since v14
- Modern tooling (Biome, native test runner) works better with ESM
- Enables tree-shaking for consumers
- Aligns with browser JavaScript

**Trade-off**: Breaking change for CommonJS consumers who use `require()`. They must use dynamic `import()` or update their code.

### 2. Node.js 22+ Requirement

**Decision**: `"engines": { "node": ">=22" }`

**Rationale**:
- Node 22 is current LTS (as of 2026)
- Enables use of native `node:test` runner
- Enables `node:util` parseArgs (replaces yargs)
- Stable ES2024 features without transpilation
- Previous constraint (`>=9 <=14`) was absurdly outdated

**Trade-off**: Users on older Node versions cannot use this library. This is acceptable because Node 14 reached EOL in April 2023.

### 3. pnpm as Package Manager

**Decision**: `"packageManager": "pnpm@10.6.1"`

**Rationale**:
- Faster than npm
- Better disk space efficiency via hard links
- Stricter dependency resolution (prevents phantom dependencies)
- Enforced via corepack

**Trade-off**: Users unfamiliar with pnpm need to learn it. However, `npm install` still works for consumers.

## Tooling Decisions

### 4. Biome Over ESLint

**Decision**: Replace ESLint + eslint-config-standard + plugins with Biome

**Rationale**:
- Single tool for linting AND formatting (replaces ESLint + Prettier)
- Written in Rust - significantly faster
- Simpler configuration (one `biome.json` vs multiple ESLint configs)
- Active development with modern defaults

**Configuration choices**:
```json
{
  "javascript": {
    "formatter": {
      "quoteStyle": "single",      // Match existing code style
      "semicolons": "asNeeded",    // Modern JS convention
      "trailingCommas": "none",    // Match existing code style
      "arrowParentheses": "asNeeded"
    }
  }
}
```

**Trade-off**: Different rule set than ESLint standard. Some warnings differ. Import organization is stricter.

### 5. node:test Over Jest/Mocha/Vows

**Decision**: Use Node.js native test runner

**Rationale**:
- Zero dependencies for testing
- Built into Node.js, so always available
- TAP output format
- Native async/await support
- `describe`/`test` API familiar to developers

**Trade-off**:
- Less feature-rich than Jest (no snapshot testing, mocking is manual)
- The library (vows) was a testing framework itself - we're now testing it with a different paradigm
- Some tests needed conversion from callback-style to Promise-style

### 6. c8 Over nyc for Coverage

**Decision**: Replace nyc with c8

**Rationale**:
- Uses V8's built-in coverage (faster, more accurate)
- Better ESM support
- Simpler configuration
- nyc had issues with ES modules

### 7. GitHub Actions Over Travis CI

**Decision**: Migrate from `.travis.yml` to `.github/workflows/ci.yml`

**Rationale**:
- Travis CI has declined significantly since 2020
- GitHub Actions is industry standard
- Better integration with GitHub PRs
- Matrix builds for multiple Node versions and platforms

**CI Matrix**:
```yaml
matrix:
  node-version: ['22', '24']
  os: [ubuntu-latest, macos-latest]
```

## Dependency Decisions

### 8. Removing lodash

**Decision**: Replace lodash utilities with native JavaScript

**Replacements**:
| lodash | Native |
|--------|--------|
| `_.isFunction(x)` | `typeof x === 'function'` |
| `_.isString(x)` | `typeof x === 'string'` |
| `_.isNumber(x)` | `typeof x === 'number' && !Number.isNaN(x)` |
| `_.isArray(x)` | `Array.isArray(x)` |
| `_.isObject(x)` | `x !== null && typeof x === 'object'` |
| `_.isUndefined(x)` | `x === undefined` |
| `_.isNull(x)` | `x === null` |
| `_.isNil(x)` | `x == null` |
| `_.isFinite(x)` | `Number.isFinite(x)` |
| `_.isRegExp(x)` | `x instanceof RegExp` |
| `_.keys(x)` | `Object.keys(x)` |
| `_.size(x)` | `Object.keys(x).length` |
| `_.each(x, fn)` | `for (const k in x) { fn(x[k], k) }` |
| `_.assign(a, b)` | `Object.assign(a, b)` |
| `_.clone(x)` | `[...x]` or `{...x}` |
| `_.concat(a, b)` | `[...a, ...b]` |
| `_.hasIn(obj, key)` | `Object.hasOwn(obj, key)` |
| `_.isEmpty(x)` | Custom check (see below) |

**isEmpty implementation**:
```javascript
const empty =
  actual == null ||
  (Array.isArray(actual) && actual.length === 0) ||
  (typeof actual === 'object' && Object.keys(actual).length === 0) ||
  (typeof actual === 'string' && actual.length === 0)
```

**Rationale**: lodash adds 70KB+ to bundle. Native methods are sufficient and faster in modern V8.

### 9. Removing async Library

**Decision**: Replace `async.eachSeries` and `async.each` with native patterns

**Original pattern**:
```javascript
async.eachSeries(items, (item, callback) => {
  doSomething(item, callback)
}, (err) => {
  // done
})
```

**Replacement pattern** (sequential):
```javascript
let index = 0
const runNext = () => {
  if (index >= items.length) {
    callback(null)
    return
  }
  const item = items[index]
  doSomething(item, (err, result) => {
    if (err) {
      callback(err)
      return
    }
    index++
    runNext()
  })
}
runNext()
```

**Replacement pattern** (parallel):
```javascript
let completed = 0
let hasError = false
for (const item of items) {
  doSomething(item, (err, result) => {
    if (hasError) return
    if (err) {
      hasError = true
      callback(err)
      return
    }
    completed++
    if (completed === items.length) {
      callback(null)
    }
  })
}
```

**Trade-off**: More verbose code, but removes a dependency and is more explicit about control flow.

### 10. Removing yargs

**Decision**: Replace yargs with `node:util` parseArgs

**Original**:
```javascript
const argv = require('yargs')
  .help('h')
  .argv
```

**Replacement**:
```javascript
import { parseArgs } from 'node:util'

const { values, positionals } = parseArgs({
  allowPositionals: true,
  options: {
    help: { type: 'boolean', short: 'h' }
  }
})
```

**Rationale**: Native API, zero dependencies, sufficient for vows CLI.

### 11. Removing CoffeeScript

**Decision**: Remove CoffeeScript support entirely

**What was removed**:
```javascript
// This registers a hook so that coffeescript modules can be loaded
require('coffeescript/register')
```

**Rationale**:
- CoffeeScript usage is negligible in 2026
- Adds complexity to CLI
- coffeescript v1.12.7 was from 2017
- No test files used CoffeeScript in meaningful ways

**Trade-off**: Users with `.coffee` test files must transpile manually. This is acceptable given CoffeeScript's decline.

## Source Structure Decisions

### 12. lib/ → src/ Rename

**Decision**: Move source files from `lib/` to `src/`

**Rationale**:
- `src/` is modern convention (matches flatlock, most modern projects)
- `lib/` historically implied compiled output
- Clearer separation: `src/` = source, `dist/` = compiled types

### 13. Export Structure

**Decision**: Conditional exports with TypeScript types

```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./src/index.js"
    },
    "./assert": {
      "types": "./dist/assert.d.ts",
      "default": "./src/assert.js"
    }
  }
}
```

**Rationale**:
- Enables `import vows from 'vows'` and `import * as assert from 'vows/assert'`
- TypeScript types are generated to `dist/`
- Source served directly (no build step for JS)

## TypeScript Decisions

### 14. TypeScript for Types Only

**Decision**: Use TypeScript to generate `.d.ts` files, not to compile source

**tsconfig.json**:
```json
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": false,          // Don't type-check JS
    "declaration": true,        // Generate .d.ts
    "emitDeclarationOnly": true // Only emit types
  }
}
```

**Rationale**:
- Source remains plain JavaScript (easier to debug)
- TypeScript consumers get type definitions
- No build step for source code
- Matches flatlock approach

**Trade-off**: Without `checkJs: true`, we don't get TypeScript's static analysis benefits during development. JSDoc annotations could be added later for stricter checking.

### 15. @types Dependencies

**Added**:
- `@types/debug` - Types for the debug package
- `@types/node` - Node.js built-in types

**Rationale**: Required for TypeScript to understand imports.

## Semantic Decisions in Code

### 16. Preserving Callback Semantics

**Challenge**: Vows has a unique callback pattern where topics can be:
1. Synchronous (return a value)
2. Asynchronous via `this.callback`
3. Asynchronous via Promise

**Critical behavior preserved**:
```javascript
// Sync callback detection
if (tdres === undefined) {
  // Async - wait for this.callback
} else if (tdres instanceof Promise) {
  // Promise - wait for resolution
} else {
  // Sync - use return value immediately
}
```

**Bug discovered**: If a teardown/topic function returns `undefined` and doesn't call `this.callback`, the test hangs. This was existing behavior, not introduced by modernization. Tests must either:
- Return a non-undefined value (sync)
- Call `this.callback` (async callback)
- Return a Promise (async promise)

### 17. atMostOnce Wrapper

**Preserved**: The `atMostOnce` function guards against callback being called multiple times.

**Modernization**: Changed from `function() { arguments }` to `(...args) =>` for cleaner syntax and to satisfy Biome's `noArguments` rule.

### 18. isNaN Naming Conflict

**Problem**: Exporting `isNaN` shadows the global `isNaN`

**Solution**:
```javascript
export function isNaNValue(actual, message) {
  nodeAssert.ok(Number.isNaN(actual), message || 'Argument must be NaN')
}

// Alias for backward compatibility
export { isNaNValue as isNaN }
```

**Rationale**: Maintains API compatibility while avoiding the shadow warning.

## Test Migration Decisions

### 19. Converting Vows Tests to node:test

**Original vows pattern**:
```javascript
vows.describe('test')
  .addBatch({
    'When X': {
      topic: () => something,
      'it does Y': (err, result) => {
        assert.equal(result, expected)
      }
    }
  })
  .export(module)
```

**New node:test pattern**:
```javascript
describe('test', () => {
  test('When X it does Y', async () => {
    await new Promise(resolve => {
      vows.describe('...')
        .addBatch({...})
        .run((err, broken, successes, failures) => {
          assert.equal(successes, 1)
          resolve()
        })
    })
  })
})
```

**Key insight**: We're testing the vows library itself, so we wrap vows test runs in Promises to integrate with node:test's async model.

### 20. Handling done() vs async/await

**Problem**: Initial tests used `done` callback style which caused issues with node:test.

**Solution**: Convert all tests to `async` functions with `await new Promise(resolve => ...)`.

**Why this works better**: node:test's handling of the `done` parameter can be inconsistent with callback-based code that also uses internal callbacks (like vows). Using explicit Promise wrapping gives us full control.

## Future Considerations

1. **JSDoc Annotations**: Could add JSDoc types to enable `checkJs: true` in tsconfig for better type safety.

2. **Deprecation**: Vows as a testing framework is largely superseded by Jest/Vitest. This modernization keeps it functional but doesn't add new features.

3. **API Changes**: The modernization preserves backward compatibility. A future v2.0 could consider breaking changes like:
   - Removing the export() method (CommonJS artifact)
   - Making all operations Promise-based
   - Simplifying the batch/topic/test hierarchy

4. **Bundle Size**: The library is now much smaller without lodash/async/yargs. Could be further reduced by removing debug in production.
